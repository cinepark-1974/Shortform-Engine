# 👖 BLUE JEANS SHORTFORM ENGINE v2.8

> 막장 공식 + 1분 클리프행어 + 과금 전환점 설계  
> **22클릭 → 100화 숏폼 드라마 시나리오 완성**

© 2026 BLUE JEANS PICTURES

---

## 개요

Shortform Engine은 **1~2분 × 80~100화** 세로형(9:16) 숏폼 드라마 시나리오를  
기획부터 집필까지 하나의 엔진 안에서 완결하는 양산형 집필 도구입니다.

- 1편(100화) 시나리오를 **3~5일**에 완성
- **매주 1편** 생산 가능한 시스템
- 드라마박스 / 비글루 / 탑릴스 등 글로벌 숏폼 플랫폼 유통 기준 충족
- 기존 글(소설/시나리오/웹툰/실화)을 막장 숏폼으로 자동 변환

---

## 핵심 수치

| 항목 | 값 |
|------|------|
| 에피소드 길이 | 1~2분 (세로 9:16) |
| 총 에피소드 | 80~100화 |
| 에피소드당 글자 수 | 500~800자 |
| 클리프행어 | 매 화 끝 필수 |
| 첫 과금 관문 | 숫자로 입력 (기본 10화, 무료 5화형이면 5) |
| 총 화수 | 20 / 30 / 50 / 80 / 90 / 100화 |
| 타겟 관객 | 30~50대 여성 중심, 모바일 |
| 총 클릭 수 | **22회** (컨셉 1 + 아크 1 + 집필 20) |
| AI 모델 | claude-sonnet-4-6 (속도 우선) |

## 기능

### TAB 1 — 새 숏폼 만들기

| 단계 | 내용 |
|------|------|
| **공통 설정** | 작품 톤(조용한 톤 / 독한 톤) · 주인공 향(여성향 / 남성향) · 첫 과금 관문(8 / 10 / 16화) · 첫 자막 형식(배지형 / 문장형 / 없음) — 탭 위에서 한 번 고르면 모든 단계에 적용 |
| **STEP 1 컨셉** | 막장 공식 선택 → 주인공/악역/비밀 입력 → 컨셉 자동 생성 |
| **STEP 2 아크** | 100화 시즌 아크 설계 → EP별 1줄 요약 + 클리프행어 유형 + 과금 포인트 |
| **STEP 3 집필** | 블록 20개 × 5화 = 100화 대본 스트리밍 집필 |
| **STEP 4 다운로드** | 전체 TXT + 아크 CSV 저장 |

### TAB 2 — 기존 글 → 숏폼 변환

텍스트를 붙여넣으면:
- 원본 분석 (핵심 갈등 / 활용 가능한 요소 / 숏폼에 안 맞는 이유)
- 막장 공식으로 변환 전략 설계
- 파일럿 EP1 대본 자동 생성
- "이 컨셉으로 100화 만들기" 버튼으로 STEP 1 파이프라인 연결

## 막장 공식

| 공식 | 설명 | 과금 포인트 |
|------|------|-------------|
| **재벌 복수** | 가난한 여주 → 재벌가 → 학대 → 비밀 → 역전 | 출생의 비밀 |
| **능력 각성** | 무시당하는 주인공 → 1화에 능력 발현 → 하나씩 꺾기 | 능력의 주인 공개 |
| **귀환 / 재회** | 5년 후 돌아온 사람 + 아이의 정체 | 아이 아버지 폭로 |
| **복수극** | 배신당함 → 새 정체 → 하나씩 무너뜨리기 | 첫 복수 성공 |
| **번개 결혼** | 버림받은 날 처음 본 남자와 혼인신고 → 남편은 숨겨진 재벌 | 남편의 정체 공개 |
| **이혼 후 후회남** | 무시당하던 아내가 도장 찍고 떠남 → 남편이 뒤늦게 매달림 | 떠난 아내의 정체 |

## 설치 및 실행

### 로컬 실행

```bash
git clone https://github.com/your-org/shortform-engine.git
cd shortform-engine
pip install -r requirements.txt
streamlit run main.py
```

`.streamlit/secrets.toml` 생성:

```toml
ANTHROPIC_API_KEY = "sk-ant-..."
```

### Streamlit Cloud 배포

1. GitHub 레포 생성 후 파일 4개 업로드
2. [streamlit.io/cloud](https://streamlit.io/cloud) → New app
3. Repository 선택 → Main file: `main.py`
4. Advanced settings → Secrets:

```toml
ANTHROPIC_API_KEY = "sk-ant-..."
```

5. Deploy

## 사용 방법

### 새 숏폼 만들기

1. **공통 설정 선택** — 작품 톤 / 주인공 향 / 첫 과금 관문 / 첫 자막 형식 (컨셉을 만들기 전에 고릅니다)
1. **막장 공식 선택** — 택1 또는 커스텀 아이디어 입력
2. **주인공 설정** — 이름/나이/직업 + 처한 상황 (최대한 불쌍하게)
3. **악역 설정** — 이름/나이/직업 + 관객이 분노하는 행동
4. **핵심 비밀** — EP 몇 화에서 드러나는지 포함해서 2~3개
5. **시즌 질문** — 이 드라마의 핵심 질문 1줄
6. **컨셉 생성** 클릭
7. **아크 생성** 클릭 → 100화 테이블 확인
8. **블록 1~20** 순서대로 클릭 → 5화씩 대본 생성
9. **전체 TXT 다운로드**

### 기존 글 변환

1. **TAB 2** 선택
2. 원본 텍스트 붙여넣기 (최대 3,000자)
3. 변환할 막장 공식 선택
4. **숏폼으로 변환** 클릭
5. 분석 결과 + 파일럿 EP1 확인
6. 마음에 들면 **이 컨셉으로 100화 만들기** 클릭

## 버전 기록

### v2.8 (2026-11-21) — 문장형 숏폼 제목

- 제목 규칙을 "10자 이내"에서 문장형으로 바꿨습니다. 뒤집는 장치 + 뜻밖의 처지 + 걸린 것(숫자)을 25~45자로 쓰고 "…"로 끊습니다. "[인물]의 식탁" 같은 명사 한 덩이 제목은 쓰지 않습니다.
- 커스텀 아이디어나 프로듀서 노트에 "제목:"으로 적어 두면 그 제목을 그대로 씁니다.
- 기존 글 변환 탭의 제목도 같은 규칙입니다.
- v2.8.1: 100화 컨셉(비밀 8개)이 길어져 답이 중간에 잘리던 것을 고쳤습니다(컨셉 답 길이 한도 6,000 → 10,000). v2.7에서 넣은 전제 점검 고정 설정(temperature 0)은 배포 서버에서 받아들이지 않아 뺐습니다. 전제 점검 답이 흔들리는 문제는 남아 있습니다.

### v2.7 (2026-11-21) — 100화 아크 재진단: 비밀 일정표, 아크 자동 점검

v2.6으로 「과부 셋」 100화 아크를 배포 화면에서 뽑아 읽고 고쳤습니다.

진단:
- 컨셉은 비밀 8개를 EP10~95에 흩어 놓았지만, 아크는 그 일정표를 받지 못하고 있었습니다. 그래서 EP80에 터져야 할 비밀(약 바꿔치기)을 EP7에 꺼내 EP77까지 다섯 번 되풀이했고(1차, 2차, 세 번째, 재개, 재조작), EP55·EP70 비밀은 아크에 나오지 않았습니다.
- "도둑 모함"이 EP45, 63, 83에 세 번 나왔습니다("재모함").
- summary가 사건 대신 규칙 이름이었습니다: "첫 응징", "세 번째 작은 응징", "과금 보상".
- 블록 국면 이름 "신뢰 한 칸"이 두 번 나왔습니다.
- 같은 전제가 전제 점검에 한 번은 통과, 한 번은 불합격했습니다.

교정:
| 항목 | v2.6 | v2.7 |
|------|------|------|
| 아크가 받는 비밀 | 없음 | 비밀 일정표: 이미 터진 것 / 이 청크에서 터뜨릴 것 / 아직 감출 것 |
| 아크 점검 | 없음 | 청크마다 자동 점검. "재-, n번째, n차", 규칙 용어뿐인 summary, 겹치는 국면 이름이 있으면 한 번 다시 설계 |
| 수법 재사용 | 막는 규칙 없음 | 한 번 쓴 수법 금지, 10화 묶음마다 싸움의 물건이 바뀜 (예시 포함) |
| 뒤 청크가 아는 것 | 화별 사건 | 화별 사건 + 이미 쓴 국면 이름 |

v2.7.1 추가 교정 (v2.7로 EP1~20을 뽑아 읽은 뒤):
- EP10에 터질 비밀(보험 수익자 변경)이 EP1 욕실 씬에서 먼저 새어 나왔습니다. 블록 집필에도 비밀 일정표를 넘겨, 뒤에 터질 비밀과 그 물건을 미리 쓰지 않게 했습니다.
- 작가가 정한 "EP1 엔딩 대사"가 화 중간에 들어가고 뒤에 씬이 붙었습니다. 엔딩 대사로 정한 것은 그 화의 마지막 대사가 되도록 했습니다.

### v2.6 (2026-11-21) — 100화를 끌고 갈 이야기 분량

「단짠단짠」 100화에서 같은 폭로("형이야")가 여덟 번 되풀이된 원인을 고쳤습니다. 뒤쪽 화를 설계하고 쓸 때 앞에서 무슨 일이 있었는지 엔진이 거의 모르고 있었습니다.

| 항목 | v2.5 | v2.6 |
|------|------|------|
| 핵심 비밀 개수 | 화수와 상관없이 3개 | 화수에 맞춤: 30화까지 3개, 50화 4개, 80화 6개, 90·100화 8개 |
| 비밀 배치 | 규칙 없음 | 처음부터 끝까지 흩어 놓음. 이웃한 두 비밀 사이 15화 이하 |
| 아크 뒤쪽 청크가 아는 것 | 앞 청크의 세 문장 요약 | 요약 + 앞의 모든 화 사건 장부(EP n: 사건) |
| 블록 집필이 아는 것 | 직전 원고의 끝 300자 | 앞의 모든 화 사건 장부 + 직전 원고의 끝 |
| 판 바꾸기 | 규칙 없음 | 10화마다 새 무기·새 비밀·편 바뀜·걸린 것 커짐 가운데 하나 |
| 되풀이 | 막는 규칙 없음 | 이미 드러난 비밀·정체는 다시 폭로하지 않고 결과만 이어받음. 블록 국면 이름이 겹치지 않음 |

- 대본 출력 형식과 컨셉·아크 JSON의 항목 이름은 바뀌지 않았습니다. secrets 목록의 개수만 늘었습니다.
- 배포 화면에서 100화 아크를 실제로 뽑아 확인하는 일은 아직 하지 못했습니다(크롬 연결 불안정). 가짜 AI 시험과 프롬프트 점검 도구로만 확인했습니다.

### v2.5 (2026-11-21) — 문서에서 가져오기, 빈 칸 자동 채우기

다른 곳에서 쓴 기획서를 그대로 얹어서 시작할 수 있습니다.

| 항목 | v2.4 | v2.5 |
|------|------|------|
| 컨셉 입력 | 일곱 칸을 손으로 적음 | **문서에서 가져오기**: 파일을 올리거나 글을 붙여넣으면 일곱 칸과 막장 공식이 채워짐 |
| 읽는 파일 | 없음 | PDF, 워드(DOCX), 한글(HWP·HWPX), TXT, MD, JSON |
| 문서에 없는 칸 | 손으로 적음 | AI가 문서의 인물·사건에 맞춰 지어서 채움 (끌 수 있음) |
| 채운 근거 | 없음 | 칸마다 "문서에서 가져옴 / AI가 지음 / 그대로 둠 / 비어 있음"을 표시 |
| 빈 칸 | 그대로 둠 | **빈 칸 자동 채우기** 버튼: 적어 둔 칸은 두고 나머지만 채움 |
| 총 화수 | 손으로 고름 | 문서에 화수가 적혀 있고 선택지(20·30·50·80·90·100)에 있으면 맞춤 |

- 이미 적어 둔 칸은 건드리지 않습니다. "이미 적은 칸도 덮어쓰기"를 켰을 때만 바꿉니다.
- 문서의 인물 이름·관계·사건은 그대로 옮깁니다. 고쳐 쓰지 않습니다.
- 긴 문서는 앞 3/4과 뒤 1/4, 합쳐 6만 자만 읽습니다.
- 스캔한 그림 PDF, 암호 걸린 파일, 옛 워드(.doc)는 읽지 못하고 사유를 알려 줍니다.
- 새 파일 `doc_import.py`(문서 글자 뽑기), `requirements.txt`에 pypdf·olefile 추가.
- 아크 영역 제목의 "100화" 고정 글자를 "시즌 아크 설계"로 바꿨습니다.
- 커스텀 아이디어에 적은 것(예: "EP1 엔딩 대사")이 컨셉 단계에서만 쓰이고 아크·집필에는 넘어가지 않던 것을 고쳤습니다. 이제 "작가가 정해 둔 것"으로 아크와 블록 집필에 그대로 넘어갑니다.
- 블록 기본 감정 모드: 아크가 정한 감정이 한 화라도 비면 블록 전체가 기본 콤보로 바뀌던 것을, 빈 화만 메우도록 고쳤습니다. 로맨스 축이 없는 작품에는 유혹·스윗·설렘을 넣지 않습니다. 기본 콤보는 블록 번호가 아니라 전체에서의 위치로 고릅니다(30화 작품에서도 맞게).
- 대본 출력 형식(EP 줄, [자막] 줄, S# 줄, 인물 대사 줄)은 바뀌지 않았습니다.
